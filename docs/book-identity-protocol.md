# 三端书籍身份协议（v1）

桌面端、Android 端和 WebDAV 交换数据均使用同一个 `readingStatsKey` / `bookIdentity`。它只由书名和作者决定，不使用本地书籍 ID、设备 ID 或文件哈希。

## 生成规则

1. `null` 书名或作者当作空字符串；空作者不填入“未知作者”。
2. 对每一项分别按 ECMAScript `String.trim().replace(/\s+/g, ' ').toLowerCase()` 规范化。空白包括 U+0009 至 U+000D、U+0020、U+00A0、U+1680、U+2000 至 U+200A、U+2028、U+2029、U+202F、U+205F、U+3000、U+FEFF。首尾空白移除，内部连续空白变成一个 U+0020；大小写折叠不随设备语言改变。不进行 Unicode NFC/NFKC 归一化。
3. 连接 `规范化书名 + U+000A + 规范化作者`，按 UTF-8 编码，计算 SHA-256，输出 64 位小写十六进制。
4. 两项都为空时，哈希输入仍是一个换行字节 `0A`。

## 历史数据

Android 旧版使用 `规范化书名 + "::" + 规范化作者`，其中 Kotlin `trim()` 与默认 `Regex("\\s+")` 的空白范围不同。读取时仅在能用记录中的书名、作者重算出旧哈希时映射到统一 key。未知哈希应保留，避免误关联。示例：`三体::刘慈欣` 的旧哈希为 `f430d8053b26af0addcc37200dabb798f426276b5aed0566e319c262e0a05354`。

书籍本地 ID 保留。迁移前保存 `books.json`、`bookmarks.json`、`reading_stats.json` 的原始副本。相同设备、日期、书籍的旧新统计累计行可能是同一份同步快照；没有事件级 ID 时，不把两行相加，保留时长与字数的较大累计值和较新时间。该规则可能低估真正独立产生的两段阅读，原始备份用于人工核对。

发布前应拿真实 WebDAV 全量和增量快照分别从桌面、Android 双向恢复，核对书籍数量、本地 ID、书签关联及每设备每日统计总量。测试快照应先复制到隔离的 WebDAV 路径，不覆盖线上备份。
